# v0.2.0 — Per-Tenant Overrides Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Each task is one TDD loop (write failing test → red → green → commit). Do not bundle tasks.

**Goal:** Activate per-tenant customization of pipeline, SLA fields, templates, and source vocabulary — without forking core code. A tenant on Standard tier can flip to a stricter confidence threshold, swap to the manual-review pipeline, and upload a custom xlsx template, all through the web Settings page, with admin impersonation still showing identical behavior.

**Architecture (in 3 sentences):**
The DB grows a `tenant_overrides` table holding JSON-patch documents keyed by `(tenant_id, scope, target_id)`. At request time, `OverrideResolver` (already shipped in `packages/core/src/ocr_to_report/core/overrides/`) is applied to the loaded profile / target / pipeline / SLA dict *before* the pipeline runs, producing a fully resolved tenant-specific config. New `/v1/tenant/config` and `/v1/pipelines` endpoints expose CRUD; the web Settings page renders a tab per scope with a JSON-patch editor and a live "resolved baseline" diff preview.

**Tech Stack:**
- DB: PostgreSQL JSONB column + GIN index; first real Alembic migration.
- Core: existing `apply_overrides` from `core.overrides.resolver` (no changes expected).
- API: FastAPI dependency injection — a new `get_tenant_config` dep that the existing `get_repos` consumes.
- Web: React + react-query + a small monaco-or-textarea-based JSON editor with live `apply_overrides` preview via a `POST /v1/tenant/config:preview` endpoint.
- Blob store: existing `BlobStore` interface for uploaded xlsx templates (keyed by `tenant/{id}/templates/{target_id}/{template_key}/<sha256>.xlsx`).

import asyncio
import pytest
from alembic.config import Config
from alembic import command
from ocr_to_report.adapters.db import get_engine, dispose_engines

@pytest.mark.integration
async def test_baseline_migration_recreates_schema(tmp_path) -> None:
    db_url = f"sqlite+aiosqlite:///{tmp_path}/m.db"
    cfg = Config("alembic.ini")
    cfg.set_main_option("sqlalchemy.url", db_url.replace("+aiosqlite", ""))
    cfg.set_main_option("script_location", "migrations")
    command.upgrade(cfg, "head")
    engine = get_engine(db_url)
    async with engine.connect() as conn:
        names = await conn.run_sync(lambda c: list(c.dialect.get_table_names(c)))
    assert {"tenants", "api_keys", "jobs", "transcripts", "audit_log"} <= set(names)
    await dispose_engines()

Schema:
```python
class TenantOverride(Base, TimestampedMixin):
    __tablename__ = "tenant_overrides"

    id: Mapped[uuid.UUID] = mapped_column(primary_key=True, default=uuid.uuid4)
    tenant_id: Mapped[uuid.UUID] = mapped_column(
        ForeignKey("tenants.id", ondelete="CASCADE"), nullable=False, index=True,
    )
    # 'pipeline' | 'sla' | 'profile' | 'target' | 'template'
    scope: Mapped[str] = mapped_column(String(32), nullable=False)
    # Sub-id for the override target — e.g. profile id, target id, template key.
    # NULL for tenant-wide scopes (pipeline, sla).
    target_id: Mapped[str | None] = mapped_column(String(120), nullable=True)
    patches: Mapped[list[dict[str, Any]]] = mapped_column(
        JSONB if dialect == 'postgres' else JSON,
        nullable=False, default=list,
    )
    enabled: Mapped[bool] = mapped_column(Boolean, default=True, nullable=False)

    __table_args__ = (
        UniqueConstraint("tenant_id", "scope", "target_id", name="uq_tenant_override_scope"),
        Index("ix_tenant_override_lookup", "tenant_id", "scope", "enabled"),
    )
```

## Task 6: Custom xlsx template upload

**Files:**
- Modify: `packages/api/src/ocr_to_report/api/routers/templates.py`
- Modify: `packages/adapters/src/ocr_to_report/adapters/render/xlsx.py`

Endpoint: `POST /v1/templates/{target_id}/{template_key}` accepts multipart `template_file` (xlsx). The upload is validated (xlsx magic byte + openpyxl can open it) then stored in blob at `tenant/{id}/templates/{target_id}/{template_key}/<sha256>.xlsx`. A `tenant_overrides` row is upserted with `scope=template`, `target_id=<target_id>`, `patches=[{"op":"set","path":"templates[<template_key>].blob_key","value":"…"}]`.

The renderer is taught to: if the resolved target config has a `blob_key` on a template, fetch it from blob and render against it instead of the shipped file.

## Risks + escape hatches

- **Alembic baseline drift.** If `alembic revision --autogenerate` produces extra/missing columns vs `Base.metadata.create_all`, the existing test suite will fail at `db_setup`. Fix by hand-editing `0001_baseline.py` until `pytest packages/adapters -m integration` is green.
- **Per-request override fetch is N+1.** Memoize on `request.state` (Task 4). If telemetry shows it's still a hot path, add an in-memory LRU keyed by `(tenant_id, last_updated_at)` invalidated by audit log entries.
- **Custom xlsx templates break the renderer.** Validate uploaded xlsx aggressively: openpyxl must open it AND it must contain all template-key cell anchors. Reject otherwise with a clear 400.
- **JSON-patch UX is hostile.** v0.2 ships raw + previews. v0.9.0 (in roadmap) adds a visual editor; do not let scope creep pull that forward.
