## 1. What we're shipping

Tenants supply their own Anthropic API key via the Settings page; the
platform routes their jobs through that key instead of the
platform-billed default. Cost reports separate `platform`-billed from
`byok` usage so v0.4.0 invoicing can ignore the BYOK rows.

**YAGNI scope, deliberate:**
- Only **Anthropic** is wired as a real concrete adapter in v0.3.0.
  The existing OpenAI / Vertex / Google stubs in
  `adapters/vision/stub_adapters.py` stay stubs. v0.7.0 — "Provider
  expansion" — promotes them to first-class adapters when there's a
  customer driving the requirement.
- No region-pinning logic (the roadmap entry mentions `region` on the
  table; we ship the column but don't act on it. v0.6.0 / v0.8.0
  surfaces consume it.)
- No "test connection" button on the Settings tab — we validate the
  key on PUT by making a single zero-cost Anthropic API call (the
  `/v1/models` listing). v0.4.0 can polish this into a richer "test
  it before saving" UI.
- No model picker — the SLA tier's `primary_model` + `fallback_model`
  stay the model authority. BYOK only swaps the credentials.

**User stories shipped:**

> *As a tenant with an Anthropic Enterprise contract, I supply my own
> `ANTHROPIC_API_KEY` and the platform routes my jobs through it.*

**User stories deferred to v0.7.0:**

> *As an EU tenant, I require all vision calls to go to Vertex AI in
> europe-west1 — no Anthropic.* — depends on real Vertex adapter.

> *As a tenant on Standard, I want Sonnet-only (no Haiku-first)
> because my documents are noisy.* — depends on model picker. The
> roadmap's "v0.3.0" entry implies this was bundled; YAGNI says split.

## 2. Architecture

```
Request flow (BYOK path):

  POST /v1/transcripts
        │
        ├── authenticate (existing)
        ├── get_repos (existing)
        ├── get_resolved_tenant_config (existing, v0.2.0)
        ├── NEW: get_active_tenant_credentials(provider="anthropic")
        │           │
        │           └── reads tenant_provider_credentials row,
        │               unwraps encrypted_api_key via per-tenant DEK
        │
        └── vision_router.select(credentials=...)
                                 ▲
                                 │ NEW: optional override at call time
                                 ▼
                     AnthropicVisionAdapter.extract(
                         request, override_api_key=<plaintext>
                     )

DB:

  tenant_provider_credentials
  ─────────────────────────────────────────────────────────
  id                 UUID PK
  tenant_id          UUID FK tenants.id     (RLS partition key)
  provider           text  ENUM("anthropic", "openai",
                              "google_vertex", "tesseract")
  encrypted_api_key  BYTEA — envelope-encrypted with the per-tenant
                            DEK. Same crypto as transcripts.
  model_overrides    JSONB DEFAULT '{}' — opt-in per-call model swap
                            (v0.3.0 ships the column; the resolver
                            ignores it. v0.7.0 reads it.)
  region             TEXT  NULL — provider-region (v0.3.0: column only)
  active             BOOL  DEFAULT TRUE — soft-disable without delete
  created_at         TIMESTAMPTZ
  updated_at         TIMESTAMPTZ
  rotated_at         TIMESTAMPTZ NULL — last key swap; audit-tracked

  UNIQUE (tenant_id, provider) WHERE active = TRUE
    -- one active credential per (tenant, provider). To rotate, mark
    -- the old one inactive in the same txn that inserts the new one.
    -- The partial unique index requires postgres; on sqlite the unit
    -- test suite leans on a transaction-level enforcement in
    -- TenantProviderCredentialRepo.upsert.

  alembic migration: 0003_tenant_provider_credentials.py
  RLS: standard tenant-scoped policy via `app.tenant_id` GUC.

  usage_records.billing_path     TEXT DEFAULT 'platform'
                                     CHECK ∈ ('platform', 'byok')

  alembic migration: 0004_usage_records_billing_path.py
```

### Task 3: Vision adapter accepts a per-call API key override
- **Files:**
  - Modify: `packages/adapters/src/ocr_to_report/adapters/vision/anthropic_adapter.py`
  - Modify: `packages/adapters/src/ocr_to_report/adapters/vision/protocol.py`

- Each `VisionAdapter.extract(request, *, override_api_key: str | None = None)`
  accepts an optional per-call credential. The Anthropic adapter
  constructs a one-shot `AsyncAnthropic(api_key=override_api_key)` when

  path.
- `ProviderRouter.select()` is a no-op pass-through that hands the
  override down. The router is **not** what decides BYOK vs platform —
  that decision happens in the request handler (Task 4) which then
  passes the credential to the router/adapter.
- **Test:** `packages/adapters/tests/test_anthropic_adapter_byok.py`
  - With `override_api_key=None`, the platform client is used.
  - With `override_api_key="sk-ant-…"`, a fresh client is constructed
    with that key. Verified via the mock's recorded constructor
    arguments.
- **Commit:** `feat(vision): per-call api_key override on adapters`.

### Task 5: `GET / PUT / DELETE /v1/tenant/providers`
- **Files:**
  - Create: `packages/api/src/ocr_to_report/api/schemas/providers.py`
  - Create: `packages/api/src/ocr_to_report/api/routers/providers.py`
  - Modify: `packages/api/src/ocr_to_report/api/routers/__init__.py`
  - Modify: `packages/api/src/ocr_to_report/api/app.py`
- Endpoints:
  - `GET /v1/tenant/providers` — list. Returns one row per
    `(provider, active=True)` with the API key REDACTED to
    `sk-ant-…<last 4>`. Never echoes plaintext, EVER. Postman won't
    see it; the WebUI doesn't need it.
  - `PUT /v1/tenant/providers/{provider}` — upsert. Body:
    `{api_key: string, model_overrides?: object, region?: string}`.
    Server validates the key against Anthropic's `/v1/models` (cheap;
    rejects bad keys with HTTP 400). Persists encrypted. Audits.
  - `DELETE /v1/tenant/providers/{provider}` — soft-disable
    (`active=False`). Audits with `provider.byok_revoked`.
- The provider enum is `Literal["anthropic", "openai", "google_vertex",
  "tesseract"]` — server accepts all four but the PUT validation
  step accepts ONLY `"anthropic"` in v0.3.0; PUT for other providers
  returns 501 with a "shipped in v0.7.0" note.
- **Test:** `packages/api/tests/test_providers_api.py`
  - Happy path: PUT with valid key, GET returns redacted view, DELETE
    soft-disables.
  - PUT with invalid Anthropic key → 400, no row persisted.
  - PUT for `provider="openai"` → 501.
  - PUT for unknown provider → 422.
- **Commit:** `feat(api): /v1/tenant/providers CRUD`.

## 4. Risks called out for the implementer

- **Decryption-error fallback path.** If a tenant's DEK rotation
  invalidates an old encrypted key, the request must NOT crash with
  500. The dep should treat decryption errors the same as "no BYOK
  row" → fall back to platform, log an alarming WARN with the
  credential id. Task 4's test should cover this.

- **The Anthropic key validation in PUT** is a network call to
  `api.anthropic.com/v1/models`. Mock it in tests. Cache validation
  results for 60s so repeated PUTs of the same key don't hammer
  Anthropic.

- **API key in logs.** Standard structlog rules apply; the
  `EnvelopeEncryptor` already redacts via its `__repr__`. But the new
  PUT handler must not log the request body. Audit entry stores
  `credential_id`, never the key itself or its prefix.

- **`billing_path` default migration.** The
  `0004_usage_records_billing_path.py` migration MUST default existing
  rows to `'platform'` — they were platform-billed by definition.

- **Multi-region keys (v0.6.0 prep).** The `region` column lands in
  v0.3.0 but isn't read. v0.6.0 / v0.8.0 will gate region-restricted
  tenants on it. Don't drop the column even though it's unused.

## 5. Acceptance criteria for v0.3.0

A v0.3.0 release passes when:

- [ ] Two tenants can run the same transcript through `anthropic`
      with **different** API keys; the requests succeed against the
      respective accounts.
- [ ] `GET /v1/usage` shows separate counts for platform-billed
      vs BYOK-billed jobs.
- [ ] An admin viewing audit logs sees `provider.byok_invoked`,
      `provider.byok_revoked`, and `provider.byok_rotated` entries
      for the tenant.
- [ ] Web Settings → Providers tab end-to-end: PUT a key, GET
      reflects it (redacted), DELETE removes it.
- [ ] PUT with an invalid Anthropic key returns 400 with a clear
      "key validation failed" body.
- [ ] All postgres integration tests + schemathesis contract tests
      continue to pass.
- [ ] Demo deployed to GitHub Pages still renders the static
      Settings → Providers tab (with all rows disabled — no backend).
