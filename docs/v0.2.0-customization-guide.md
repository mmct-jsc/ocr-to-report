# v0.2.0 — Per-tenant customization guide

`v0.2.0` activates the override stack that lets each tenant tailor the
pipeline, SLA, templates, and source vocabulary without forking the
engine. This guide walks through what you can change, where to change
it, and the wire shape behind each surface.

If you'd rather just point-and-click, skip to [§5](#5-using-the-console).

---

## 1. Mental model

```
┌─────────────────────────────────────────────────────────────┐
│ Shipped baseline                                            │
│   sla_tier preset · target_bundle · pipeline yaml           │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼  (resolved per request)
┌─────────────────────────────────────────────────────────────┐
│ Tenant config (this release)                                │
│   tenant.pipeline_id    ← direct column                     │
│   tenant_overrides[*]                                       │
│     scope="sla"      patches list                           │
│     scope="target"   per-target_id patches list             │
│                      (incl. templates[<key>].blob_key)      │
│     scope="profile"  per-profile_id patches list            │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼  applied to baseline
┌─────────────────────────────────────────────────────────────┐
│ Resolved view (what the request handler sees)               │
└─────────────────────────────────────────────────────────────┘
```

Every override is **additive**: omit a field and you get the baseline
back. Send an explicit empty list to clear a scope. The merged result
is computed once per request and cached on `request.state` so multiple
downstream consumers (SLA gate, renderer override lookup, ...) share a
single database read.

## 2. What you can customize

| Surface | Scope | Granularity | Touched by |
|---|---|---|---|
| Active pipeline | `tenant.pipeline_id` | One value per tenant | Pipeline tab / `PUT /v1/tenant/config { pipeline_id }` |
| SLA fields | `scope="sla"` patches | Per-field override on top of the tier preset | SLA tab / `PUT /v1/tenant/config { sla_patches }` |
| Template files | `scope="target"` patches with path `templates[<key>].blob_key` | Per `(target_id, template_key)` slot | Templates tab / `POST /v1/templates/{target_id}/{template_key}` |
| Profile vocabulary | `scope="profile"` patches | Per `profile_id` | Vocabulary tab / `PUT /v1/tenant/config { profile_overrides }` |

Pipelines, source profiles, and target systems still ship in the repo
as YAML bundles. v0.2.0 doesn't introduce a "create my own pipeline"
path — that's `v0.4.0` workflow customization on the roadmap. What it
does give you: **switch which shipped pipeline runs**, and **override
specific fields on top of it**.

## 3. Wire shape

### `GET /v1/tenant/config`

Resolved view. Use this to render the current effective config.

```json
{
  "sla": {
    "tier": "standard",
    "confidence_threshold": 0.95,
    "park_low_confidence": true,
    "...": "..."
  },
  "pipeline_id": "with_manual_review_v1",
  "sla_patches": [
    {"op": "set", "path": "confidence_threshold", "value": 0.95}
  ],
  "profile_overrides": {},
  "target_overrides": {
    "us-hs.v1": [
      {"op": "set", "path": "templates[grade_9].blob_key",
       "value": "tenant/<id>/templates/us-hs.v1/grade_9/<sha>.xlsx"}
    ]
  }
}
```

### `POST /v1/tenant/config:preview`

Same body as `PUT`; returns the resolved view as if the patches were
saved. **Never writes anything.** The console's "see the diff before
you save" uses this.

### `PUT /v1/tenant/config`

Per-scope replace-semantic. Every field is optional. Omit a field to
leave that scope untouched; send an explicit empty list/dict to clear
it.

```json
{
  "pipeline_id": "with_manual_review_v1",
  "sla_patches": [
    {"op": "set", "path": "confidence_threshold", "value": 0.95}
  ],
  "target_overrides": {
    "us-hs.v1": [
      {"op": "set", "path": "vocabulary.curriculum_note", "value": "tenant-tagged"}
    ]
  }
}
```

SLA patches dry-run through strict Pydantic re-validation **before**
anything is persisted, so an out-of-range threshold or unknown enum
gets a 400 with the field name. Profile/target patches are only
wire-format-validated at write time (op/path well-formed); deeper
validation happens at apply time when a job actually runs against
that bundle.

### `POST /v1/templates/{target_id}/{template_key}`

Multipart form, single field `template_file` (the xlsx). The server:

1. Confirms the slot exists in the shipped catalogue (404 if not).
2. Magic-byte-checks for `PK\x03\x04` (415 if not a ZIP).
3. Tries `openpyxl.load_workbook` (400 if it can't open it).
4. Stores at `tenant/{tenant_id}/templates/{target_id}/{template_key}/<sha256>.xlsx`.
5. **Merges** the resulting `templates[<key>].blob_key` patch into any
   existing `scope="target"` row so co-located vocabulary patches
   survive.

Returns:

```json
{
  "target_id": "us-hs.v1",
  "template_key": "grade_9",
  "blob_key": "tenant/.../grade_9/<sha>.xlsx",
  "sha256": "<hex>",
  "size_bytes": 12345
}
```

### `DELETE /v1/templates/{target_id}/{template_key}`

Reverts the slot to the shipped template. Drops the `blob_key` patch
from the row (keeping any other target-scope patches). Best-effort
blob cleanup. 204 on success, 404 if no override exists.

## 4. SDK shortcuts

### TypeScript

```ts
import { Client } from "@ocr-to-report/sdk";

const client = new Client({ baseUrl, apiKey });

// Read the resolved view.
const cfg = await client.tenantConfig.get();
console.log(cfg.sla.confidence_threshold, cfg.pipeline_id);

// Switch pipelines + raise the SLA threshold in one PUT.
await client.tenantConfig.replace({
  pipeline_id: "with_manual_review_v1",
  sla_patches: [{ op: "set", path: "confidence_threshold", value: 0.95 }],
});

// Upload a custom xlsx template.
await client.templates.upload({
  targetId: "us-hs.v1",
  templateKey: "grade_9",
  file: myXlsxBlob,
  filename: "tenant-branded.xlsx",
});

// Revert.
await client.templates.delete({
  targetId: "us-hs.v1",
  templateKey: "grade_9",
});
```

### Python

```python
from ocr_to_report.sdk_py import Client, TenantConfigUpdate

client = Client(base_url="...", api_key="sk_live_...")

# Read.
cfg = client.tenant_config.get()
print(cfg.pipeline_id, cfg.sla["confidence_threshold"])

# Write.
client.tenant_config.replace(TenantConfigUpdate(
    pipeline_id="with_manual_review_v1",
    sla_patches=[{"op": "set", "path": "confidence_threshold", "value": 0.95}],
))

# Upload.
with open("tenant-branded.xlsx", "rb") as f:
    client.templates.upload(
        target_id="us-hs.v1",
        template_key="grade_9",
        file_bytes=f.read(),
        filename="tenant-branded.xlsx",
    )
```

Both clients ship sync + async variants. `AsyncClient.tenant_config`
mirrors the surface verbatim.

## 5. Using the console

`/settings` now has five tabs:

| Tab | Purpose |
|---|---|
| **General** | API endpoint, signed-in key, theme. Unchanged from v0.1.0. |
| **Pipeline** | Radio list of the three shipped pipelines (`default_v1`, `with_manual_review_v1`, `batch_economy_v1`) with a "what this does" panel. Save writes `tenant.pipeline_id`. |
| **SLA** | Per-field override toggles for `confidence_threshold`, `park_low_confidence`, `retention_days`, `provider_policy`. Each row shows the tier baseline next to the override input — flip the toggle to pin a value. |
| **Templates** | Lists every `(target_id, template_key)` slot. Drag an xlsx onto a row, or click Upload. Already-overridden slots get an "overridden" badge + a Revert button. |
| **Vocabulary** | Raw JSON-patch editor for `profile_overrides`. Power-user surface. Save is disabled while the textarea content isn't valid JSON. |

The Settings tabs are WAI-ARIA compliant — left/right arrow keys jump
between tabs, Home/End jump to first/last, the active tab's panel
takes focus on activation. The whole thing is reachable from the
keyboard without a mouse.

## 6. What this does *not* change

- **Existing tenants see no behavior change** unless they actively
  save a patch. The resolver short-circuits on the empty-patches path.
- **Schema:** v0.2.0 adds the `tenant_overrides` table via Alembic
  migration `0002`; no existing columns or constraints changed.
  Operators upgrading: `alembic upgrade head` (or set
  `OCR2R_AUTO_MIGRATE_ON_BOOT=true` for development).
- **SLA tier remains an admin-managed field.** Tenants override
  individual SLA fields above their tier preset; only an admin can
  promote a tenant from Standard to Premium via
  `PATCH /v1/admin/tenants/{id}`.
- **Pipeline list is fixed.** Tenants choose between shipped
  pipelines. Authoring a custom pipeline lands in `v0.4.0`.

## 7. Open questions for `v0.3.0`

The two surfaces v0.2.0 deliberately doesn't address:

- **Provider choice (BYOK).** Anthropic-only today; the SLA preset's
  `provider_policy` toggles `single`/`fallback`/`ensemble` shapes but
  every concrete adapter still calls Anthropic. v0.3.0 lights up
  OpenAI + Google Vertex as first-class fallback targets and adds the
  per-tenant API-key vault.

- **Model picker within a provider.** Today the pipeline yaml fixes
  `claude-haiku-4-5` as primary + `claude-sonnet-4-6` as fallback.
  v0.3.0 surfaces a "Models" tab in Settings letting tenants pick
  from Haiku / Sonnet / Opus (when the provider chosen exposes them).
